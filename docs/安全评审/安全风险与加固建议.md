# 安全风险与加固建议

> 评审日期：2026-08-16  
> 评审范围：后端接口、认证授权、数据库访问、前端渲染、CSV 导入与日志处理

## 1. 总体结论

当前项目已经具备基础安全防护，SQL 注入风险较低，前端 XSS 也有 Vue 默认转义保护，但尚不能认为已经完整防御常见 Web 攻击。

| 风险类型 | 当前状态 |
| --- | --- |
| SQL 注入 | 基本已防住 |
| XSS | 有基础防护，缺少纵深防御 |
| 越权访问 | 后端有角色和资源归属校验 |
| 密码存储 | 已使用 BCrypt |
| 登录暴力破解 | 尚未防护 |
| JWT 伪造与失效 | 尚未完整防护 |
| 跨表用户名唯一性 | 存在并发竞争窗口 |
| AI Key 存储 | 已使用 AES-GCM 加密 |
| 接口限流 | 已实现单实例内存限流 |

## 2. 已具备的安全措施

### 2.1 SQL 注入防护

- MySQL 查询使用 Spring Data JPA 的 `findByXxx`、`findById`
- MongoDB 查询使用 `MongoTemplate` 和 `Criteria`
- 未发现 `JdbcTemplate`、原生 SQL 字符串拼接或 `createNativeQuery`

### 2.2 XSS 基础防护

- Vue 模板使用文本插值，默认对文本内容进行转义
- 未发现 `v-html`、`innerHTML`、`document.write`
- 用户名、姓名、题目、CSV 错误信息等动态内容不会作为 HTML 直接渲染

### 2.3 认证与授权

- 使用 Spring Security + JWT
- 后端按 `ADMIN`、`TEACHER`、`STUDENT` 进行接口隔离
- 登录密码使用 BCrypt 加密后保存
- 学生查询提交结果时校验资源归属，降低横向越权风险

### 2.4 文件上传

- 上传文件限制为 5MB
- 仅允许 `.csv` 扩展名
- CSV 使用 `commons-csv` 解析

### 2.5 错误与日志

- 全局异常处理不向前端返回堆栈
- 密码不会写入业务日志
- 已关闭 Spring 请求体调试日志，避免明文密码进入日志文件

## 3. 现存安全风险

### 3.1 JWT 密钥硬编码

**风险等级：高**

`backend/src/main/resources/application.yml` 中写死了 JWT 密钥：

```yaml
jwt:
  secret: codejudge-platform-jwt-secret-key-change-in-production-2026
```

由于该密钥已经进入项目文件，任何能够获取代码或仓库权限的人都可以伪造合法 JWT。

**加固建议**

- 生产环境通过环境变量注入 JWT 密钥
- 本地开发密钥与生产密钥分离
- 使用足够长度的随机密钥
- 避免将真实密钥提交到 Git

### 3.2 角色修改、删除或改密后旧 token 仍然有效

**风险等级：高**

当前 JWT 只包含用户名和角色，认证过滤器不会重新查询数据库。因此：

- 用户角色被修改后，旧 token 在过期前仍使用旧角色
- 用户被删除后，旧 token 在过期前仍可访问
- 用户密码被修改后，旧 token 在过期前仍然有效

**加固建议**

- 在用户表中增加 token 版本号
- JWT 中写入 token 版本
- 认证过滤器在关键请求中重新检查用户状态
- 或引入 Redis token 黑名单

### 3.3 登录接口没有限流

**风险等级：高**

当前 `/api/auth/login` 没有登录失败次数限制、IP 限流或验证码，存在账号密码暴力破解风险。

**加固建议**

- 对同一用户名连续失败次数进行限制
- 对同一 IP 的登录请求进行限流
- 连续失败达到阈值后增加锁定时间或验证码

### 3.4 缺少安全响应头和 CSP

**风险等级：中**

当前 XSS 防护主要依赖 Vue 自动转义，没有额外的浏览器安全响应头。如果未来某处误用 `v-html`，缺少 CSP 会增加风险。

**建议增加**

```text
Content-Security-Policy
X-Content-Type-Options: nosniff
X-Frame-Options: DENY
Referrer-Policy: no-referrer
```

可以在 Nginx 中配置，也可以在 Spring Security 中增加响应头过滤器。

### 3.5 跨表用户名唯一性存在并发竞争窗口

**风险等级：中**

用户名唯一性当前由 `AdminUserService` 依次查询学生表、教师表和管理员表完成。高并发下，两个请求可能同时通过检查，然后在不同角色表中创建相同用户名。

**加固建议**

- 优先方案：将三张用户表统一为一张用户表，并为用户名建立数据库唯一索引
- 当前方案：增加数据库层面的跨表唯一性约束，或对用户名创建统一索引表
- 至少对关键创建流程增加分布式锁或数据库唯一键校验

### 3.6 token 保存在 localStorage

**风险等级：中**

前端将 JWT 保存在 `localStorage` 中。一旦发生 XSS，攻击者可以直接读取 token。由于当前尚未配置 CSP，该风险会被放大。

**加固建议**

- 增加严格的 CSP，限制可执行脚本来源
- 保持所有动态内容走 Vue 文本插值，避免 `v-html`
- 如果后续支持 Cookie，使用 `HttpOnly`、`Secure`、`SameSite` Cookie 保存凭证

### 3.7 CSV 上传需要继续增强

**风险等级：低**

当前已限制文件大小和扩展名，但尚未限制：

- 最大数据行数
- CSV 内容类型与扩展名的一致性
- 文件名长度

**加固建议**

- 增加最大导入行数，例如 5000 行
- 对上传文件名做长度和字符校验
- 继续使用 `commons-csv`，不手工解析 CSV

### 3.8 系统配置模块安全状态

系统配置模块已经增加以下安全措施：

- AI API Key 使用 AES-GCM 加密后保存到数据库
- 查询接口只返回 `hasApiKey` 和掩码，不返回完整 Key
- 配置审计日志对敏感配置不记录旧值和新值
- 配置表使用乐观锁，避免并发修改后写覆盖先写
- 登录、AI 调用和代码提交已实现全局、单用户、单 IP 限流
- 配置更新后缓存立即刷新

仍需注意：

- AES-GCM 默认开发密钥保存在 `application.yml`，生产环境必须通过 `SYSTEM_CONFIG_ENCRYPTION_KEY` 注入
- 解密后的 AI Key 会在后端内存中短暂存在，不能写入日志或响应
- 当前限流使用单实例进程内计数，多个后端实例部署时会被绕过，需要改为 Redis 分布式限流
- `X-Forwarded-For` 只在可信反向代理环境下可靠，直连应用时客户端可以伪造
- 配置审计日志需要定期归档，避免审计表无限增长

## 4. 推荐加固顺序

1. JWT 密钥外置并替换当前默认密钥
2. 实现 token 失效机制
3. 增加登录限流
4. 增加 CSP 和安全响应头
5. 解决跨表用户名唯一性的并发问题
6. 增加 CSV 最大行数限制
7. 生产环境替换系统配置加密默认密钥
8. 多实例部署时使用 Redis 分布式限流

## 5. 当前可接受范围

以下问题在当前本地开发和原型阶段可以接受，但正式上线前必须处理：

- JWT 默认密钥
- token 未即时失效
- 登录接口无限流
- 跨表用户名唯一性并发窗口
- 系统配置 AES-GCM 默认开发密钥
- 单实例内存限流
