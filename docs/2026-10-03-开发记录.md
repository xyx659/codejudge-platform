# 2026-10-03 开发记录

> 日期：2026-10-03
> 记录范围：把学生端「测试」按钮从浏览器本地 Java→JS 玩具转换器，改走后端 Docker 真实编译运行（`POST /api/student/run`）

## 一、根因回顾

「测试」按钮此前走的是 `QuestionSolve.vue:231 → runLocalTests() → jsRunner.js:264`，全程在浏览器 Web Worker 里跑，从不经过后端。所谓「编译」是 `jsRunner.js:210` 的 `new Function(...)`；所谓「转换」是 `jsRunner.js:40-57` 的正则白名单，只支持 `new int[]{...}`、`new int[n]`、`Arrays.asList`、`int[] arr =`、`int i = 0`、`Integer.parseInt` 等极少数写法。平台上 36 道 METHOD 题全是数据结构题（HashMap / Stack / ListNode），学生代码必然出现泛型声明、自定义类声明、增强 for 等未翻译写法，翻译产物直接是非法 JS，报「Invalid left-hand side in assignment」「Unexpected identifier 'prev'」等。

**结论**：本地自测当年做成了玩具转换器，而不是复用已有的 Docker 评测引擎，一旦代码超出白名单就「编译失败」。

## 二、本次实现

把「测试」按钮改走后端，复用现成的 Docker 评测链路，只跑样例用例、不写提交记录、不触发 AI 评审。

### 后端

1. **新增 `POST /api/student/run`**（`StudentController`），入参 `RunRequest{questionId, sourceCode, testCases}`，出参 `RunResult{compileError, results}`。
   - 说明：用户原始建议是 `POST /api/run`，这里放到 `/api/student/**` 下（`/api/student/run`），是为了复用现有路由与鉴权约定（`SecurityConfig` 已对 `/api/student/**` 施加 `STUDENT` 角色），无需改安全配置；如需顶层 `/api/run` 只需移动映射并补一条 `requestMatchers`。
2. **新增 `RunService`**：同步复用 `CodeRunner`（生成 Main 包装）+ `WorkspacePacker`（打包）+ `JudgeContainerClient`（容器编译运行）+ `SystemConfigService.getJudgeRuntimeConfig()`（超时/内存/CPU 与正式判题一致），逐用例运行并返回「名称/通过/实际/期望/说明/耗时」。
   - 用例来源：请求里带了 `testCases` 就用请求里的（考试页是随机抽取子集）；为空则回退题目全部用例。
3. **抽取 `JudgeOutputMatcher`**（纯静态）：把原先 `DockerJudgeEngine` 私有的输出比对逻辑（精确匹配 / 浮点模糊 / 数组无序比对）抽成共用类，`DockerJudgeEngine` 与 `RunService` 共用，保证「测试」与「最终提交」判卷口径一致。

### 前端

4. `api/student.js` 新增 `runCode(data)` → `POST /student/run`。
5. `QuestionSolve.vue` / `ExamSolve.vue` 的 `runTest()` 改为调 `runCode`，并补 `catch` 兜底（原 `runLocalTests` 从不 reject，改走后端请求可能网络失败）；移除 `jsRunner` 导入。

## 四、技术要点

1. **判题口径一致**：抽 `JudgeOutputMatcher` 后，正式判题与样例自测用同一套比对逻辑，避免两处漂移。
2. **无状态自测**：`RunService` 不落库、不触发 AI 评审，仅同步返回结果，因此「测试」和「提交」彻底解耦。
3. **复用而非重写**：Main 生成、数据结构辅助类（ListNode/TreeNode/Node）、`javac`/`java` 命令、容器安全参数全部复用 `CodeRunner` + `JudgeContainerClient`，新增代码集中在编排层。
