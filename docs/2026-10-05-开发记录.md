# 2026-10-05 开发记录

> 日期：2026-10-05
> 记录范围：判题引擎从「仅 Java」重构为多语言（Python + Go）后端判题链路

## 一、背景与目标

原判题链路（`DockerJudgeEngine` → `CodeRunner` → `JudgeContainerClient`）处处写死 Java：生成 `Main.java` 包装、`javac`/`java` 命令、镜像 `eclipse-temurin:17`、`.class` 产物复用，全部耦合在单一 `CodeRunner` 类里。本次按「各语言原生签名」约定，抽出语言抽象层，新增 Python、Go 两个语言处理器，实现**后端判题链路**的多语言路由；前端语言选择器 / AI 提示词多语言化留待下一轮。

设计文档见 `docs/自研容器判题服务设计.md`（`LanguageHandler` 接口 + 注册表 + 每语言镜像 + 资源模板）。

## 二、核心抽象

### `LanguageHandler` 接口（新增）

每种语言一个实现，封装「源码 → 编译 → 运行」的全部语言相关行为：

- `language()` / `image()` / `sourceFileName()` / `wrapperFileName()`
- `requiresCompile()`（Java/Go=true，Python=false）
- `compileCommand()` / `runCommand(inputFile)`
- `parseSignature(String)` → `MethodSignature(returnType, methodName, paramTypes)`
- `generateMethodWrapper` / `generateDesignWrapper` / `generateStdioWrapper`
- `helperSources(signature)`（数据结构定义文件）、`extractClassName`、`selectRunFiles`

### `LanguageHandlerRegistry`（新增）

`@Component`，构造注入 `List<LanguageHandler>`，按小写语言名路由；`null`/空串回退 Java，显式传了不支持的语言（如 C++）抛 `BadRequestException`。

## 三、三个语言处理器

### `JavaLanguageHandler`（由原 `CodeRunner` 迁移）

保留全部原逻辑（`Json` 解析/序列化、`ListNode`/`TreeNode`/`Node` 四形态、三种判题模式），仅改名实现接口：`generateMain`→`generateMethodWrapper`、`generateDesignMain`→`generateDesignWrapper`、`generateStdioMain`→`generateStdioWrapper`、`requiredHelperSources`→`helperSources`；新增 `selectRunFiles`（过滤 `.class`）；镜像改为 `@Value` 注入、保留默认值 `eclipse-temurin:17`。`MethodSignature` 抽为顶层 record。

### `PythonLanguageHandler`（新增）

- 镜像 `python:3.12-alpine`，`requiresCompile()=false`，运行命令 `python3 main.py < input`。
- 生成自包含 `main.py`：内嵌 `ListNode`/`TreeNode`/`Node` 结构 + `split/value/find_pos` 输入解析 + `parse/serialize`，再 `exec(compile(solution.py))` 注入学生源码到全局命名空间（使类型注解与结构可见），按签名位置传参调用 `Solution().method(...)`。
- 输入/输出契约与 Java 完全一致（LeetCode 键值式输入、无空格序列化），同一道题 `testCases` 可跨语言复用。
- 支持 `int/float/bool/str/List[...]/Optional[...]/ListNode/TreeNode/Node`；DESIGN 用 `json.loads` 直接解析两行输入，STDIO 用 `exec(..., {'__name__':'__main__'})` 透传。

### `GoLanguageHandler`（新增）

- 镜像 `golang:1.22-alpine`，编译命令 `GOCACHE=/tmp/gocache go mod init judge && go build -o solution .`（离线、可写缓存），运行命令 `chmod +x solution && ./solution < input`（补齐打包时丢失的执行位）。
- 生成自包含 `main.go`（与 `solution.go` 同属 `package main` 一起编译）：标量/切片/字符串/布尔等 JSON 原生类型直接用 `encoding/json` 的 `Unmarshal`/`Marshal`（Go 的 json 对切片、嵌套切片、字符串、布尔、数值的输出天然与 LeetCode 无空格格式一致），`ListNode`/`TreeNode`/`Node` 用自定义解析/序列化。
- `selectRunFiles` 只保留可执行文件 `solution`；支持 `int/int64/float64/string/bool/[]int/[][]int/[]string/[][]byte` 与三类结构。

## 四、编排层改造

| 文件 | 变更 |
|------|------|
| `DockerJudgeEngine.java` | 注入 `LanguageHandlerRegistry` 取代 `CodeRunner`；按 `question.getLanguage()` 取处理器；编译分支按 `requiresCompile()`，产物复用走 `selectRunFiles`，镜像按 `handler.image()` 逐调用传入 |
| `RunService.java` | 同上（样例自测链路同口径） |
| `JudgeContainerClient.java` | 移除构造注入的单一镜像字段，`run/compile` 增 `image` 参数；按镜像名缓存 `readyImages`（`ConcurrentHashMap.newKeySet()`），`ensureImage`/`createContainer` 按镜像 |
| `QuestionService.java` | `normalizeLanguage` 放开：`java→Java`、`python/python3/py→Python`、`go/golang→Go`，其余仍拒绝 |
