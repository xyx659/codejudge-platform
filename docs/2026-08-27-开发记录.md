## 三、M5 自研容器判题服务（Step 1–4）

> 详见 [自研容器判题服务设计](自研容器判题服务设计.md)。本项目用 Docker 沙箱在容器内编译 + 运行学生代码并逐用例判题，替换 `StubJudgeEngine` 占位实现。

### Step 1 — 定方法签名方案

- `Question` 实体新增 `judgeMode`（METHOD/STDIO）与 `methodSignature`（自包含签名，如 `int[] twoSum(int[], int)`）
- `QuestionSaveRequest` 新增 `methodSignature` 字段，前端 `AdminQuestions` 表单加方法签名输入框
- `LeetCodeQuestionProvider` 从 LeetCode 元数据解析方法签名；`QuestionService` 对无签名老题做「按首个用例输入推断全 int 参数」的兜底

### Step 2 — 异步化与并发限流

- `AsyncConfig` 新增 `judgeExecutor` 评测专用线程池（`@EnableAsync`）
- `JudgeService.trigger` 改为 `@Async("judgeExecutor")`，进入执行体后经动态 `Semaphore(maxConcurrent)` 抢占许可，把「同时评测」数量限制在配置范围内

### Step 3 — 容器客户端

- 新增 `JudgeContainerClient`：封装一次「无状态单命令」的 Docker 容器全生命周期（create → `docker cp` 写工作目录 → start → wait 带超时 → 读日志 → 清理）
- 超时按「优雅停止 → 强杀 → 强制删除」三级兜底，防止容器残留
- 安全参数：`--network none`、`--memory/--memory-swap`、`--nano-cpus`、`--pids-limit 64`、`--read-only + --tmpfs /tmp`、`--cap-drop ALL`、`--user nobody`
- `compile` 方法在编译成功后额外回拷容器工作目录（含 `.class` 产物），供逐用例运行复用；镜像按需自动拉取（双重检查锁）
- `DockerConfig` 用 `DockerClientImpl.getInstance(config, httpClient)` 构建 `DockerClient`

### Step 4 — 源码包装

- 新增 `CodeRunner`：解析方法签名 → 生成自包含 `Main` 包装类（读 stdin 键值式输入 → 按签名解析入参 → 调 `Solution.methodName(...)` → 打印结果），并拼出 `javac` / `java` 命令
- 新增 `WorkspacePacker`：用 `commons-compress` 把「文件名 → 内容」打成 tar / 解包，供 `docker cp` 传输与编译产物回拷
- `CodeRunnerTest` 覆盖签名解析、`Main` 生成与实跑单用例
