# 自研容器判题服务设计

> 状态：已完成（Step 1–9 全部实现，2026-08-28）
> 关联任务：M5「实现自研容器编译测试服务（Docker 沙箱内编译运行 + 判题）」
> 关联代码：`JudgeEngine` / `JudgeService` / `DockerJudgeEngine` / `CodeRunner` / `JudgeContainerClient` / `AiReviewService`

## 一、目标

把占位实现 `StubJudgeEngine`（只打日志、判卷状态永远停在 `PENDING`）替换为真实判题引擎：在 Docker 沙箱里编译并运行学生提交的代码，逐用例比对输出，回写判卷结果，并触发 AI 白盒评审。

**已定决策**

| 项 | 决策 |
|---|---|
| 语言范围 | 仅 Java（预留多语言扩展点） |
| 源码形态 | 完整类（学生提交 `public class Solution {...}`，判题侧生成 `Main` 包装类） |
| 判定粒度 | 黑盒逐用例比对 + 白盒 AI 评审同开 |
| 数据结构 | `ListNode` / `TreeNode` / `Node` 作为独立 `.java` 文件注入编译，按签名自动判断 |
| 类型支持 | 43 种 LeetCode 数据类型（基本/包装/数组/列表/Map/链表/树/图） |

## 三、整体方案

核心：**`DockerJudgeEngine implements JudgeEngine`，替换已删除的 `StubJudgeEngine`**。

### 3.1 文件清单

| 文件 | 职责 | 状态 |
|------|------|------|
| `DockerJudgeEngine.java` | 核心引擎（拉数据 → 包装源码 → 编译 → 逐用例运行 → 汇总回写 → AI 评审） | 新增 |
| `CodeRunner.java` | 签名解析 + `Main.java` 生成 + 43 种类型 parse/print + 数据结构独立文件生成 | 大幅扩展 |
| `JudgeContainerClient.java` | 封装 Docker 容器的编译、运行调用与超时控制 | 已有，增强 |
| `JudgeService.java` | `@Async` + `Semaphore(maxConcurrent)` 异步限流 | 已改 |
| `AiReviewService.java` | DeepSeek API 白盒评审 | 已改 |
| `StubJudgeEngine.java` | 占位实现 | **已删除** |

### 3.2 数据结构独立文件化

`ListNode`/`TreeNode`/`Node` 不再是 `Main` 的内部类，而是独立的顶层 `.java` 文件：

- `CodeRunner.listNodeSource()` / `treeNodeSource()` / `nodeSource()` 生成源码
- `CodeRunner.requiredHelperSources(signature)` 按签名自动判断需要哪些文件
- `DockerJudgeEngine` 编译时自动注入到容器工作目录
- `Solution.java` 可直接引用 `ListNode`/`TreeNode`/`Node`

辅助方法（`parseListNode`/`qlListNode` 等）按需注入 `Main.java`：
- 签名含 `ListNode` → 注入 `HELPERS_LIST_NODE`
- 签名含 `TreeNode` → 注入 `HELPERS_TREE_NODE`
- 签名含 `Node` → 注入对应形态的 `HELPERS_NODE_*`（4 种）

## 四、核心流程（DockerJudgeEngine.judge）

```
拉数据 (submission + detail + question)
    ↓
解析签名 (CodeRunner.parseSignature)
    ↓
生成 Main.java + 注入数据结构文件 (ListNode/TreeNode/Node)
    ↓
容器内 javac 编译 (*.java)
    ├─ 编译失败 → COMPILE_ERROR，回写 stderr
    └─ 编译成功 → 提取 .class 文件
         ↓
    逐用例独立容器运行 (java Main < inputN.txt)
    ├─ 超时 → 标记超时
    ├─ 非零退出 → 运行时错误
    └─ 比对 stdout vs expected (trim)
         ↓
    按通过率算分 (passCount / total × 100)
         ↓
    回写 MySQL submissions + MongoDB submission_details
         ↓
    触发 AI 白盒评审 (DeepSeek API)
         ↓
    回写 aiReview 到 MongoDB
```

## 五、支持的数据类型（43 种）

### 基本类型（6）
`int`, `long`, `double`, `boolean`, `char`, `String`

### 包装类型（5）
`Integer`, `Long`, `Double`, `Boolean`, `Character`

### 一维数组（6）
`int[]`, `long[]`, `double[]`, `boolean[]`, `char[]`, `String[]`

### 二维数组（6）
`int[][]`, `long[][]`, `double[][]`, `boolean[][]`, `char[][]`, `String[][]`

### 一维列表（6）
`List<Integer>`, `List<Long>`, `List<Double>`, `List<Boolean>`, `List<String>`, `List<Character>`

### 二维列表（5）
`List<List<Integer>>`, `List<List<Long>>`, `List<List<Double>>`, `List<List<Boolean>>`, `List<List<String>>`

### 三维列表（1）
`List<List<List<Integer>>>`

### Map 类型（5）
`Map<Integer,Integer>`, `Map<String,Integer>`, `Map<Integer,List<Integer>>`, `Map<String,List<String>>`, `Map<String,String>`

### 链表 / 树 / 图（5 + 4 种 Node 形态）
- `ListNode`：单链表（val + next）
- `TreeNode`：二叉树（val + left + right）
- `Node`（4 种形态，由字段组合自动识别）：
  - 随机指针链表：val + next + random
  - N 叉树：val + children
  - 图（邻接表）：val + neighbors
  - 带 next 二叉树：val + left + right + next

### 序列化格式

| 类别 | 格式 | 示例 |
|------|------|------|
| 数组/列表 | `Arrays.toString()` 风格（逗号后带空格） | `[1, 2, 3]` |
| 字符串 | 带双引号 | `"hello"` |
| 2D 数组/列表 | 嵌套方括号 | `[[1, 2], [3, 4]]` |
| Map | JSON 风格（无空格） | `{"key":value}` |
| 链表 | 层序方括号 | `[1, 2, 3]` |
| 二叉树 | LeetCode 层序（null 标记） | `[3, 9, 20, null, null, 15, 7]` |
| 图 | 邻接表 | `[[2, 4], [1, 3], [2, 4], [1, 3]]` |

## 六、Docker 隔离参数（安全关键）

```
--network none      # 禁网
--memory {memoryMb}m --cpus 1
--pids-limit 64     # 防 fork bomb
--read-only --tmpfs /tmp
--cap-drop ALL --user nobody
--rm                # 用后即焚
```

镜像：`eclipse-temurin:17`（可通过 `judge.docker.image` 配置覆盖）。工作目录通过 `docker cp` 写入容器。

## 七、风险点与待决问题

1. **~~方法签名缺口~~**（已解决）：`Question` 已扩充 `methodSignature` 字段（如 `int[] twoSum(int[], int)`），`CodeRunner.parseSignature()` 解析返回类型 + 方法名 + 参数类型列表。
2. **容器冷启动**：每用例独立容器运行，单用例几百 ms～秒级。当前 50 人并发场景可接受；后续可考虑「一题一次编译 + 多用例同容器」优化。
3. **~~输入解析~~**（已解决）：支持 43 种 LeetCode 数据类型，采用 LeetCode 键值式输入（`nums = [2,7,11,15], target = 9`）。
4. **多语言**：当前仅 Java。扩展 C/Python/C++ 需新增对应 `CodeRunner` 实现 + 编译/运行命令 + Docker 镜像。
5. **~~TeacherQuestion 缺 methodSignature~~**（已解决，2026-08-29）：`TeacherQuestion` 实体补齐 `methodSignature` 字段，教师端创建/编辑题目可保存方法签名。
6. **~~qlTreeNode 序列化 NPE~~**（已解决，2026-08-29）：`ArrayDeque` 不允许 null 元素导致树序列化崩溃，改用 `LinkedList`。
