### 2. 链表/树/图数据结构独立文件化

**问题**：`ListNode`/`TreeNode`/`Node` 原先定义在 `Main` 的 static inner class 中，学生的 `Solution.java` 作为独立文件引用不到，导致编译失败。

**修复**：
- `ListNode`/`TreeNode`/`Node` 从 `Main` 内部类 → 独立 `.java` 文件
- 新增 `listNodeSource()` / `treeNodeSource()` / `nodeSource()` 方法生成源码
- 新增 `requiredHelperSources(signature)` 按签名自动判断需要哪些数据结构文件
- `DockerJudgeEngine` 编译时自动注入这些文件到容器

**按需注入**：`parseListNode`/`qlListNode`/`parseTreeNode`/`qlTreeNode` 从 `HELPERS_BASE` 拆出为 `HELPERS_LIST_NODE`/`HELPERS_TREE_NODE`，仅当签名涉及对应类型时才注入 `Main.java`，避免无关类型污染。

**Node 四种形态自动识别**：通过 `parseClassFields()` 解析辅助类定义的字段组合（`random` → 随机指针链表、`children` → N 叉树、`neighbors` → 图、`next` → 带 next 二叉树）。

### 3. 自研容器评测链路打通

**新增文件**：`DockerJudgeEngine.java`（289 行）

完整评测流程：拉数据 → 生成 `Main.java` → 容器内 `javac` 编译 → 逐用例独立容器运行 → 比对输出 → 按通过率算分 → 回写数据库 → 触发 AI 评审。

- **编译**：一次编译，`.class` 产物通过 `docker cp` 回拷宿主，逐用例复用
- **运行**：每用例独立容器，精确超时，用例间完全隔离
- **状态映射**：编译失败 → `COMPILE_ERROR`，编译超时 → `TIMEOUT`，运行完成 → `RUN_COMPLETED`
- **算分**：通过用例数 / 总用例数 × 100，四舍五入

**修改文件**：`JudgeContainerClient.java`（+31 行）—— 增强容器等待超时处理、镜像配置化（`judge.docker.image` 默认 `eclipse-temurin:17`）。

**删除文件**：`StubJudgeEngine.java`（占位实现，被 `DockerJudgeEngine` 替代）。
