## 一、今天已完成

### 1. 修复 AI 评审时间复杂度/空间复杂度为空

**问题**：学生端「我的成绩」页面查看 AI 评审详情时，时间复杂度和空间复杂度始终显示为 "—"（空值）。

**根因分析**：
1. MongoDB 中存储的 `aiReview` 对象完全没有 `timeComplexity` 和 `spaceComplexity` 字段
2. AI 模型（deepseek-chat）没有遵循 prompt 指令返回这两个字段
3. `extractJsonObject` 方法使用 `indexOf('{')` 取第一个 JSON，当 AI 返回 thinking 块时会取到错误的 JSON

**修复**（`AiReviewService.java`）：

- **Prompt 重构**：将 `timeComplexity` 和 `spaceComplexity` 移到 JSON 模板最前面，用更强的语气强调必填
  ```
  === 输出格式（严格按此结构，不得省略任何字段） ===
  {
    "timeComplexity": "分析代码中的主要算法，给出时间复杂度，如 O(n)、O(log n)、O(n^2)",
    "spaceComplexity": "分析代码中的主要算法，给出空间复杂度，如 O(1)、O(n)",
    ...
  }
  注意：timeComplexity 和 spaceComplexity 是最优先必填字段，必须是类似 O(n) 的格式字符串。
  ```

- **JSON 提取逻辑重写**：改为「从后向前找匹配的 `{`」策略，取最后一个完整 JSON 对象，避免 thinking 块干扰
  ```java
  // 原逻辑：int start = s.indexOf('{');  // 可能取到 thinking 中的 JSON
  // 新逻辑：从最后一个 '}' 向前扫描匹配 '{'
  ```

- **兜底提取**：当 AI 仍未返回复杂度字段时，用正则从 feedback 和 summary 文本中提取 `O(...)` 表达式
  ```java
  Pattern.compile(keyword + "复杂度[^O]*?(O\\([^)]+\\))")
  ```

- **thinking 模型兼容**：`callChatCompletions` 增加对 `reasoning_content` 字段的读取，兼容部分 thinking 模型的响应结构

### 2. AI 评审增加多维度评分体系

**变更**：评审从单一 `qualityScore` 扩展为 9 维度加权评分

| 维度 | 权重 | 说明 |
|------|------|------|
| correctness（正确性） | 30% | 代码能否正确解决目标问题 |
| time_complexity（时间复杂度） | 15% | 算法效率是否高效 |
| space_complexity（空间复杂度） | 10% | 内存使用是否合理 |
| edge_cases（边界与异常处理） | 10% | 边界条件处理是否完善 |
| readability（可读性与代码风格） | 10% | 命名、结构、注释是否清晰 |
| maintainability（可维护性与模块化） | 8% | 模块划分是否合理 |
| robustness（鲁棒性与容错） | 5% | 异常环境下的稳定性 |
| test_coverage（测试覆盖） | 5% | 测试用例是否充分 |
| algorithm_design（算法思想与优化） | 7% | 算法选择是否恰当 |

前端 `StudentScores.vue` 增加维度评分条形图展示。

## 四、技术要点

1. **deepseek-chat 模型特点**：不支持 thinking 模式（仅 v4-pro 支持），但仍然可能不遵循 JSON 输出格式指令
2. **JSON 提取策略**：从后向前匹配比从前往后更可靠，因为 AI 可能在 thinking 过程中产生中间 JSON
3. **兜底设计**：AI 输出不可靠时，从已有文本中用正则提取是合理的降级方案
