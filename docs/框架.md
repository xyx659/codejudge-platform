# 数智化编程考核与智能分析系统 —— 系统框架

> 依据《软件设计文档.md》与《创业训练项目申报书》补充完善

## 1. 总体架构

平台采用分层式 B/S 软件架构，自顶向下分为五层：

1. 前端展示层：面向学生、教师、管理员提供三类专属交互界面，覆盖平时作业、随堂测验、实验考核、期末机考全流程。
2. 接入与网关层：统一流量入口，负责请求转发、身份认证与鉴权、限流控制、日志记录。
3. 核心后端服务层：按职责拆分 API、评测、AI 评审、考试监控、反作弊、学情分析等服务模块。
4. 数据存储层：MySQL 存储用户、提交元数据、系统配置与审计日志，MongoDB 存储题目、提交答案与 AI 评审报告，Redis 规划承担缓存与分布式队列。
5. 基础设施层：Docker 容器化沙箱保障代码运行安全，配合定时任务实现自动化运维。

技术栈：Vue 3、Java 17 + Spring Boot 3、Redis、自研容器编译测试、DeepSeek API 或本地千问大模型、MySQL + MongoDB、Docker、Git。

## 2. 接入与网关层

网关负责统一的流量入口管理，核心功能包括：

- 请求转发：反向代理与路由分发，业务逻辑不下沉到网关
- 身份认证与鉴权：登录认证、RBAC 权限控制
- 限流控制：接口限流、AI 调用控制、提交去重
- 日志记录：登录和关键管理操作自动审计

### 2.1 开发环境代理

开发阶段由 Vite 开发服务器承担反向代理，将前端的 `/api` 请求转发到本机 Spring Boot 服务的 `8080` 端口。该代理只在本地运行 `npm run dev` 时生效，不用于生产环境。

### 2.2 生产环境反向代理

生产环境使用 Nginx 作为统一反向代理入口：

- 前端：提供 Vue 构建后的 `dist` 静态资源，并通过 `try_files` 支持 Vue Router 的 history 模式。
- 后端：将 `/api/` 请求转发到 Spring Boot 的 `8080` 端口。
- 客户端隔离：学生端、教师端和管理端通过 `/student`、`/teacher`、`/admin` 路径区分，前端路由和后端 RBAC 共同完成权限校验。

推荐部署结构：

```text
学生电脑 / 教师电脑 / 管理电脑
            │
            ▼
         Nginx
        ├── /             → frontend/dist
        └── /api/         → Spring Boot :8080
                              ├── MySQL
                              └── MongoDB
```

### 2.3 当前已实现的网关能力

- JWT 登录与三角色 RBAC 权限隔离
- 登录和代码提交接口限流
- 当前限流采用单实例进程内固定窗口，多实例部署时规划迁移到 Redis
- 登录和管理端关键写操作自动写入业务审计日志
- 系统配置修改自动写入配置审计日志
- 密码、代码、AI Key、token 等敏感字段在审计前统一脱敏

## 3. 用户端（角色与功能）

系统面向三类用户角色，各自拥有独立的功能模块：

学生端：

- 在线编程环境：多语言在线编辑、编译与运行，支持本地样例自测
- 获取题目
- 接收题目并上传代码（提交后自动判卷，无需手动触发）
- 获取学生信息和考试成绩（分数）
- 查看 AI 评审报告与个性化反馈

教师端：

- 上传题目与题库管理：题目维护、分类、组卷、自动出题
- 下发题目：覆盖平时作业、随堂测验、实验考核、期末机考
- 记录教师信息与学生信息
- 学情分析：成绩统计、能力画像、教学诊断
- 考试监考：考试状态监控与反作弊实时预警

管理端：

- 上传题目
- 教师与学生信息管理（用户与权限管理）
- 系统配置、CSV 用户导入、操作日志审计
- 全局考试监控与反作弊告警汇总

## 4. 核心后端服务层

系统拆分为多个微服务或业务模块，各司其职：

- 后端 API 服务：提供基础数据接口（题目、用户信息、提交记录等）
- 在线编程与评测服务：基于自研容器实现多语言（C/Python/Java 等）编译运行与功能测试（黑盒测试），判卷响应时间 ≤3 秒/人
- AI 评审服务：对学生代码进行白盒分析（代码质量、风格、复杂度），智能评判打分并生成个性化反馈与优化建议
- 考试监控服务：监控学生端状态，记录登录、提交时间等考试情况，记录作弊信息（反作弊）
- 反作弊服务：切屏检测、全屏锁定、行为分析、代码查重（借鉴 MOSS 思路），可疑行为实时预警
- 学情分析服务：学习数据采集、成绩统计、能力画像与教学诊断
- 异步判卷链路：提交进入 Redis 队列，Worker 异步消费，支持 50 人并发与实时进度推送
- 系统配置服务：评测参数、AI 模型配置、限流阈值和加密 AI Key
- 操作审计服务：AOP 自动采集登录和管理端写操作，异步写入审计表

安全隔离：使用 Docker 容器对代码编译和测试环境进行隔离，保障系统安全。

## 5. 数据存储层

系统采用混合存储架构，根据数据类型选择不同方案：

- MySQL：用户信息（学生/教师/管理员，含学号）、提交记录元数据（判卷摘要）、系统配置、配置审计、操作审计
- MongoDB：题目信息（含测试用例）、提交答案明细、AI 评审报告
- Redis：规划用于试卷快照、判卷队列、分布式限流计数、反作弊事件流；当前限流使用进程内内存实现
- 文件存储（MinIO/OSS）：上传附件、日志归档
- 日志与审计：操作日志、反作弊事件归档

## 6. 基础设施层

- Docker 容器化沙箱：隔离代码编译与测试环境
- 定时任务：数据备份、学情统计、缓存预热
- 双部署支持：高校机房本地化部署 + 云端（阿里云等）部署
- 轻量化运维：适配 3 人小团队，低成本、易维护

## 7. 整体数据流与教学闭环

教师/管理员通过后端上传题目（MongoDB）并下发；学生获取题目、在线编写并提交代码；代码经 Docker 沙箱内自研编译测试（黑盒），AI 服务完成白盒分析与评审；提交元数据写入 MySQL，题目、提交答案与 AI 评审报告写入 MongoDB，Redis 规划承担队列、缓存与分布式限流，当前限流使用进程内实现；考试监控服务实时记录反作弊情况并预警，学情分析服务生成能力画像与教学诊断，形成"教学 → 考核 → 学情分析 → 反馈改进"的完整闭环。

## 8. 关键指标与约束

- 判卷响应时间：≤3 秒/人
- 并发能力：机房单台服务器 50 人并发
- 支持语言：C、Python、Java 等主流编程语言
- 判卷方式：黑盒测试（功能正确性）+ 白盒分析（代码质量、风格、复杂度）
- 反作弊体系：切屏检测、全屏锁定、代码查重、行为分析
- 本地优先、弱网兼容：确保断网/限网环境下核心功能可用
