## 一、今天已完成

### 1. 抽象多语言判题基座

在判题引擎之前先抽象出一套与语言无关的接口层，为后续 Java / Python / Go / C / C++ 统一路由打基础：

- `LanguageHandler` 接口：定义 `language()`、`image()`、`sourceFileName()`、`wrapperFileName()`、`compileCommand()`、`runCommand()`、`generateMethodWrapper()`、`generateDesignWrapper()`、`generateStdioWrapper()`、`helperSources()` 等方法。
- `LanguageHandlerRegistry` 注册表：按 `language()` 字符串注册/查找各语言处理器。
- `MethodSignature` DTO：题目方法签名（返回类型 + 方法名 + 参数类型列表 + 方法名集合）。

> 注意：`DockerJudgeEngine` 目前仍硬编码走 `CodeRunner`（Java-only），尚未接入 `LanguageHandlerRegistry`。

### 2. C++ 判题处理器与数据结构头文件

实现 `CppLanguageHandler`，编译模型为 `main.cpp` 直接 `#include "solution.cpp"`（单翻译单元），`using namespace std;` 必须出现在 `#include "solution.cpp"` 之前。配套 4 个头文件：

- `lang/c_cpp/common.h`：stdin 读取、`split_top_level` 顶层分隔、标量/一维/二维数组解析、LeetCode 格式序列化打印、通用 `Queue`（BFS）。
- `lang/c_cpp/ListNode.h`：单链表 `ListNode` 解析/序列化（含带环 pos）。
- `lang/c_cpp/TreeNode.h`：二叉树 `TreeNode` 层序解析/序列化。
- `lang/c_cpp/Node.h`：多态 `Node`（next/random/children/left/right/neighbors），支持随机指针链表、N 叉树、图、填充 next 树 4 种形态。

### 3. C 判题处理器与数据结构头文件

实现 `CLanguageHandler`，编译模型为 `main.c` 直接 `#include "solution.c"`，编译命令 `gcc -std=gnu11 -O2 -o main main.c -lm`，运行 `./main < input`。配套 4 个头文件：

- `lang/c/common.h`：与 C++ 版对应的 C 实现（`read_all_stdin` 动态读入、原地破坏式 `split_top_level`、各标量/数组解析与打印、通用 `Queue`）。
- `lang/c/ListNode.h` / `TreeNode.h` / `Node.h`：与 C++ 版对应的 C 结构体实现。

C 语言采用 LeetCode 官方 C 约定：一维数组形参 `int* arr, int arrSize`；二维数组 `int** arr, int arrSize, int* arrColSize`；数组返回额外加 `int* returnSize` 出参（二维再加 `int** returnColumnSizes`）；`String` → `char*`；`boolean` → `bool`（`<stdbool.h>`）；链表/树/图 → `struct ListNode*` / `struct TreeNode*` / `struct Node*`；设计题 → `struct ClassName` + `lXxxCreate/Get/Put/Free` 命名。

## 四、技术要点

1. **单翻译单元编译模型**：学生代码 `solution.cpp` / `solution.c` 被 `main.cpp` / `main.c` 直接 `#include`，简化了跨文件调用，只需编译一个入口文件。
2. **`using namespace std;` 顺序**：必须写在 `#include "solution.cpp"` 之前，否则学生代码里的标准库符号（如 `vector`、`string`）无法解析。
3. **C 语言指针 + 长度约定**：与 C++ 的 `vector`/返回值不同，C 官方约定数组靠「指针 + 长度 + returnSize 出参」传递，处理器需按此生成形参与调用实参。
4. **Node 4 形态识别**：`Node` 有随机指针链表 / N 叉树 / 图 / 填充 next 树 4 种形态，通过方法名（`copyRandomList`、`connect`、`cloneGraph`、`levelOrder` 等）识别，避免按类型字面匹配误判（`TreeNode`/`ListNode` 含 `Node` 子串）。
5. **镜像规划**：Java `eclipse-temurin:17`、Python `python:3.12-alpine`、Go `golang:1.22-alpine`、C/C++ 共用 `gcc:13`。
6. **辅助头文件按需引入**：用词边界匹配判断签名里是否真用到 `ListNode`/`TreeNode`/`Node`，避免把无关头文件塞进包装文件。
