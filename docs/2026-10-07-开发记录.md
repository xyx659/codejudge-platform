## 七、输出比对浮点容错（本轮追加）

背景：Go 的 `json.Marshal` 对 `[]float64{1.0, 2.0}` 序列化为 `[1,2]`（丢 `.0`），而期望输出常写成 `[1.0,2.0]`，此前 `JudgeOutputMatcher` 的数组比对是逐元素字符串精确比较，会误判为「输出不符」。

改动（`service/JudgeOutputMatcher.java`，纯静态、可单测）：

- 数组元素比对从「字符串精确」升级为「数值元素允许 1e-5 误差（绝对 + 相对）」，其余字符串仍精确比较；标量浮点比对复用同一 `numbersClose` 助手，消除重复逻辑。
- 字符串元素（如 `"1"`）不会与数字元素（如 `1`）误配——`isNumeric` 对带引号 token 返回 false。

新增 `JudgeOutputMatcherTest`（5 用例：精确相等 / 标量浮点 / 数组数值近似 / 无序数组 / 字符串数字不误配）。验证：`DockerJudgeEngineTest / JavaLanguageHandlerTest / PythonLanguageHandlerTest / GoLanguageHandlerTest / JudgeOutputMatcherTest / RateLimitServiceTest / SystemConfigServiceTest` 共 43 用例全绿。

## 八、Docker 端到端联调解锁（本轮追加）

镜像拉取恢复后，用真实 Docker 沙箱跑通三语言端到端验证，暴露并修复两个 Go 特有根因。

| 文件 | 变更 |
|------|------|
| `dto/ContainerRunRequest.java` | 追加 `pidsLimit` 字段（编译放宽、运行严格，由调用方传入） |
| `service/JudgeContainerClient.java` | 新增 `PIDS_LIMIT_COMPILE=256` / `PIDS_LIMIT_RUN=64` 常量；`createContainer` 的 `withPidsLimit(64L)` 改为 `request.pidsLimit()` |
| `service/DockerJudgeEngine.java` / `service/RunService.java` | 编译阶段传 `PIDS_LIMIT_COMPILE`、运行阶段传 `PIDS_LIMIT_RUN`；运行阶段打包改 `pack(runFiles, handler.executableNames())` |
| `service/WorkspacePacker.java` | 新增 `pack(Map, Set<String> executables)` 重载，对 executables 中的文件设 0755（其余仍 0644） |
| `service/LanguageHandler.java` | 新增默认方法 `executableNames()`（返回空集） |
| `service/GoLanguageHandler.java` | 覆盖 `executableNames()=Set.of("solution")`；`runCommand` 去掉 `chmod +x`，改为 `./solution < inputFile` |

**根因一：Go 编译 `fork/exec .../asm: resource temporarily unavailable`**。`--pids-limit 64` 太低——Go 标准库并发编译会 fork 大量工具链进程触发 EAGAIN（提高内存无效，提高 pids 有效；实测 256 可过）。修复：编译阶段 pids 提到 256，运行阶段仍保持 64 防 fork bomb。

**根因二：Go 运行 `./solution` 权限 126**。`docker cp` 写入的文件属主为宿主机 uid，容器内 `nobody` 无法 `chmod`（`Operation not permitted`）；而 `WorkspacePacker.pack` 硬编码 0644 把编译产物 `solution` 的执行位打丢，`chmod +x solution && ./solution` 里 chmod 失败短路。修复：打包时按 `executableNames()` 给可执行文件设 0755（含 other 执行位），并移除 runCommand 里对宿主机属主文件无效的 chmod。

验证：`MultiLanguageRunIntegrationTest` 6 用例全绿（Python 3 + Go 3，覆盖正常通过 / 编译错误 / 输出不符）；`DockerJudgeEngineIntegrationTest` 4 用例全绿（Java 编译错误 / 正常通过 / 死循环超时 / 运行时异常）；核心单测 11 个全绿。
