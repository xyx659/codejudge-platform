# 2026-10-10 开发记录

> 日期：2026-10-10
> 记录范围：题目去语言化 + 签名统一 Java 风格 + 判分逻辑修复 —— 题库一道题支持多语言作答

## 一、今天已完成

### 1. 题目去语言化（删除题目的 `language` 字段）

题库里的题目不再绑定单一语言，语言改由「考试/提交」决定：

- `Question` / `TeacherQuestion` 实体删除 `language` 字段。
- 相关 DTO（`QuestionSaveRequest` / `QuestionRequest` / `QuestionDetail` / `QuestionSummary` / `QuestionManageDetail` / `QuestionManageSummary` / `TeacherQuestionDetail` / `TeacherQuestionSummary` / `ExternalQuestionCandidate`）及工厂方法全部去掉 `language`。
- `QuestionService` / `TeacherQuestionService` 删除 `normalizeLanguage` 与 `setLanguage`；`QuestionController` 列表接口删除 `language` 筛选参数；外部导入 provider（LeetCode/Luogu）删除候选人 `language` 参数。
- 导入模板（`import-template`）不再要求 `language` 字段；`docs/` 下 5 个题库 JSON（`question-bank-import.json` 47 题、`leetcode-questions*.json`、`test-new-features.json`）批量删除 `language` 字段。
- 前端建题表单（`AdminQuestions.vue` / `TeacherQuestions.vue`）删除语言下拉、列表「语言」列与 `form.language`；答题页 `QuestionSolve.vue` 删除「语言」展示。

### 2. 保留考试语言，判题按「提交语言」路由

- `Exam` 实体与「考试语言」字段、`TeacherExams.vue` 组卷界面原样保留；组卷选题时删除按考试语言过滤题目的逻辑。
- `Submission` 实体新增 `language` 字段（`schema.sql` 的 `submissions` 表加 `language VARCHAR(20)` 列，现有库执行 `ALTER TABLE` 补列）。
- 交卷 `StudentService.submitExam` 按 `exam.getLanguage()` 写 `submission.language`；单题直刷（非考试）暂固定 Java。
- `DockerJudgeEngine` / `RunService` 判题语言来源从 `question.getLanguage()` 改为 `submission.getLanguage()` / `RunRequest.language`。
- `StudentExamQuestion.language` 改为取考试语言，前端 `ExamSolve.vue` 自测带上 `q.language`。

### 3. 方法签名统一为 Java 风格

题库统一用 Java 风格签名存储（如 `int[] twoSum(int[], int)`），判题前按目标语言翻译：

- 新增 `SignatureConverter`：把 Java 风格签名翻译成 Go / Python 原生签名（Java/C/C++ 原生即 Java 风格，原样解析）。
- `DockerJudgeEngine` / `RunService` 在 `handler.parseSignature(...)` 前套一层 `SignatureConverter.toNative(...)`。
- 前端 `templates.js` 的 `pythonMethod/goMethod/pythonDesign/goDesign` 改为解析 Java 风格签名并翻译类型（新增 `goType` / `pyType` 映射）。

### 4. 判分逻辑修复

排查判分链路（黑盒通过率 → AI 白盒评审 → 考试总分汇总），修复三处：

- **考试总分按分值折算（严重 bug）**：`StudentService.listExamScores` 原来 `achieved += min(得分, 分值)`，把 0~100 的百分比与题目分值直接取 `min`，分值≠100 时全错。改为 `round(得分 × 分值 / 100)`。
- **AI 评分公式**：`AiReviewService.parseReview` 原来 `score = passRate×0.7 + qualityScore×0.3`，全错的代码也能靠「代码质量」拿 30 分、全对又被质量分压低。改为：全对满分、全错 0 分、仅部分通过时才掺质量分。
- **AI 缺维度分兜底**：`dimensionScores` 为空时 `qualityScore` 默认 100，不再静默归 0 扣分。

### 5. 启动验证与「0 分」排查

- 后端（JDK 17）、前端、MongoDB、MySQL、Docker 全部跑通；Python / Go 用 Java 风格签名的题真实判题通过（`两数之和` 20/20 用例，`[0,1]`）。
- 修复运行期暴露的问题：`Submission` 加 `language` 后 MySQL `submissions` 缺列导致学生题目列表 500，补 `schema.sql` + `ALTER TABLE`。
- 排查「C++ 题刷新后 0 分」：结论是考试「1010」里「环形链表」**分值 = 0**（组卷时没填分值，`TeacherExams.vue` 的 `confirmPicker` 新题分值默认 0），学生实际判题 `myScore=97` 正常，与判题无关。

## 三、遗留与说明

1. **旧数据迁移**：库里旧有的 Python/Go 原生签名题（`def ...` / `func ...`）现在会被当 Java 风格解析，需重新导入或把签名归一化为 Java 风格。
2. **单题直刷暂固定 Java**：多语言只在考试场景生效（`StudentService.submit` 单题提交 `setLanguage("Java")`、`RunService` 无语言时回退 Java），后续再补直刷语言选择。
3. **「0 分」是组卷数据问题**：分值 0 的题按 0 分计算是符合预期的；要正确出分需在组卷时给题填分值。
4. **AI 白盒评审**：仅配置了 AI API Key 时才触发，未配置时保留黑盒通过率分数；本次评分公式修复只影响后续评审。

## 四、技术要点

1. **判题语言与题目解耦**：`Submission.language` / `RunRequest.language` 是判题语言唯一来源，不再从题目取；考试交卷自动带 `exam.getLanguage()`。
2. **签名单一权威格式**：题库只存 Java 风格签名，`SignatureConverter` 在判题边界翻译成 Go/Python 原生，前端模板生成用同样的映射（`goType`/`pyType`）。
3. **百分比与分值分属两个量纲**：黑盒/AI 得分是 0~100 百分比，考试总分要 `得分 × 分值 / 100` 折算，不能直接相加或取 `min`。
4. **加 DB 字段要同步 `schema.sql` + 现有库**：`ddl-auto: none` 不会自动加列，实体加字段后需补建表语句并对存量库 `ALTER TABLE`。
